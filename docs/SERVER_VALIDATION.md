# Validations serveur et permissions host

Lot W-005 / X-006 / I-003 du 6 septembre 2026. Audit des sources locales et compilation contre le jeu local ; aucun parcours Unity exécuté. Les états W restent inchangés.

Les settings « Host permissions (clients) » exposent six booléens persistés : `AllowClientService`, `AllowClientCoupling`, `AllowClientRemoteCoupling`, `AllowClientPurchases`, `AllowClientTrainManagement`, `AllowClientTimeAdvance`. Ils valent true par défaut pour conserver la coopération existante. Le host conserve ses permissions mais ne contourne pas la readiness ni les contrôles de valeurs. Les nouvelles requests lisent les settings du host ; aucune permission fournie par le client n'est utilisée. Ce sont des permissions globales aux clients, sans rôles par joueur.

Les RPC work train, shop quote, shop purchase et licence répondent aussi NotReady lorsqu'un peer sans ServerPlayer envoie une request. Warehouses, pit stops, couplers et commandes radio historiques ne sont pas des RPC corrélés : leurs packets n'ont pas de TicketId. Aucun format corrélé n'a été inventé pour eux dans ce lot.

Les commandes remote coupling restent sans limite de proximité physique : Uncouple cible parfois un wagon éloigné dans le train. Les junctions restent utilisables à distance par map/radio. Les rotations de turntable peuvent être diffusées après le départ de l'utilisateur et n'imposent donc pas une proximité au sender. Ces exceptions ne contournent pas la readiness ni les permissions.

Limites encore ouvertes dans X-006 : le packet remote coupling ne contient ni identité du remote ni pairing autoritaire ; la permission globale ne prouve donc pas la possession d'un remote appairé. Rerail ne prouve pas encore la correspondance géométrique de Position au TrackId. Les refus historiques sur certains targets absents et les échecs métier non-RPC restent inégaux. Le mode de jeu autorisant le spawn libre, le job booklet ownership, ainsi que rotation/ownership du turntable nécessitent une suite d'audit. Les positions du joueur restent des données répliquées du client : la policy n'est pas un système anti-teleport. Les seuils physiques de 10 m et de coupler à 5 m sont des marges de tolérance, pas une mesure Unity validée. La campagne reproductible est détaillée dans [W011-W014-UNITY-CAMPAIGN.md](W011-W014-UNITY-CAMPAIGN.md).

Validation exécutée : `powershell -NoProfile -File tools/Validate.ps1`, compilation réussie, 111 tests passent dans le workspace partagé. Six tests ajoutés par ce lot couvrent distances non finies et limites, readiness/permissions host, indices, flags remote contradictoires, combinaisons UI avancées et wire round-trip des refus de permission. Les autres tests comprennent les travaux présents simultanément dans le workspace. Le log local est `validation-w005.log`.
